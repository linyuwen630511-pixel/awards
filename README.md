# 醫護教育創意設計大賞｜互動式票選與頒獎系統
**Healthcare Education Creative Awards — Voting & Ceremony**

本系統用於課堂成果發表的「簡報組」與「海報組」票選及頒獎典禮。
前端放在 **GitHub Pages**（免費），投票資料放在 **Supabase** 雲端資料庫（免費方案即可）。
防止重複投票、狀態控制與計票全部在雲端資料庫內執行，學生無法從手機端繞過。

## 一、系統內容

| 檔案 | 用途 |

## 二、部署教學

### 步驟 1：建立 Supabase 專案

1. 前往 <https://supabase.com>，用 GitHub 或 Email 註冊並登入。
2. 按 **New project**：
   - Name：例如 `healthcare-awards`
   - Database Password：按 Generate 產生，並**另外記下來**
   - Region：建議選 **Northeast Asia (Tokyo)** 或 **Southeast Asia (Singapore)**（離台灣較近）
3. 按 **Create new project**，等待約 1–2 分鐘建立完成。

### 步驟 2：建立資料庫（貼上 schema.sql）

1. 左側選單點 **SQL Editor** → **New query**。
2. 用記事本打開 `supabase/schema.sql`，**全選複製**，貼到 SQL Editor。
3. 按右下角 **Run**。看到 `Success. No rows returned` 即完成。

> ⚠️ `schema.sql` 每次執行都會**清空所有投票資料並重建名單**。正式投票開始後請勿再執行。
> 若重新執行過，需要再做一次步驟 3 的第 2 點（設定管理員）。

### 步驟 3：建立教師帳號

1. 左側選單 **Authentication** → **Users** → **Add user** → **Create new user**。
2. 輸入教師 Email 與一組強密碼，勾選 **Auto Confirm User**，按 **Create user**。
3. 回到 **SQL Editor** → **New query**，打開 `supabase/add_admin.sql`，
   把 `teacher@example.com` 改成剛剛的教師 Email，貼上並按 **Run**。
   結果應出現一列教師資料。

> 只有列在管理員名單中的帳號能操作後台。其他人即使註冊帳號也無法使用任何管理功能。
> 建議到 **Authentication → Sign In / Providers**，把 **Allow new users to sign up** 關閉，避免陌生人自行註冊。

### 步驟 4：填寫 config.js

1. 在專案頁面上方按 **Connect**，或左側選單 **Project Settings** → **API Keys**。
2. 複製：
   - **Project URL**（例如 `https://abcdefghijk.supabase.co`）
   - **Publishable key**（`sb_publishable_` 開頭）。請優先使用這一種；舊版的 `anon` key 雖然仍可使用，但 Supabase 已宣布將於 2026 年底前逐步淘汰。
3. 用記事本打開 `config.js`，填入：

```js
window.AWARDS_CONFIG = {
  SUPABASE_URL: 'https://abcdefghijk.supabase.co',
  SUPABASE_KEY: 'sb_publishable_xxxxxxxxxxxxxxxx',
  PUBLIC_SITE_URL: ''
};
```

> 這兩個值本來就是給瀏覽器使用的公開值，可以放上 GitHub。
> **絕對不要**填入 `secret key` 或 `service_role key`。

### 步驟 5：上傳到 GitHub Pages

1. 登入 <https://github.com>，右上角 **+** → **New repository**。
   - Repository name：例如 `awards`
   - 選 **Public**（免費帳號的 GitHub Pages 需要公開儲存庫）
   - 按 **Create repository**
2. 在新儲存庫頁面點 **uploading an existing file**，把本資料夾**內的所有檔案與資料夾**（包含 `vendor` 與 `supabase`）拖曳上去，按 **Commit changes**。
   - 注意：要上傳的是資料夾「裡面」的內容，`index.html` 必須在儲存庫最上層。
3. 進入儲存庫 **Settings** → 左側 **Pages**：
   - Source：**Deploy from a branch**
   - Branch：**main**，資料夾 **/(root)**，按 **Save**
4. 等待約 1–3 分鐘，頁面上方會顯示網址，例如：
   `https://你的帳號.github.io/awards/`

### 步驟 6：正式活動前的試跑（強烈建議）

1. 打開 `https://你的帳號.github.io/awards/admin.html`，用教師帳號登入。
2. 「名冊與代碼」→ **產生未發放代碼**（系統會自動下載代碼名冊 CSV）。
3. 用自己的手機掃 QR Code，以任一代碼投一次票，確認流程順暢。
4. 試跑後，回到 Supabase SQL Editor **重新執行 `schema.sql`** 與 `add_admin.sql`，資料即恢復為全新狀態。
5. 正式活動前再產生一次代碼並發給學生。

## 三、活動當天操作流程

| 時間點 | 教師操作 | 學生看到 |
|---|---|---|
| 課前 | 後台「組別與作品」填寫兩類別作品名稱；「設定」確認是否允許投自己組 | 首頁顯示「投票尚未開始」 |
| 課前 | 「名冊與代碼」產生代碼 → 列印代碼單，剪開後個別發放 | — |
| 開始 | 「QR Code」→ **投影 QR Code（全螢幕）**；按 **開始投票** | 掃描 QR → 輸入代碼 → 投票 |
| 進行中 | 「統計與名次」即時看參與率（學生看不到票數） | 送出後顯示「投票成功！」 |
| 需要時 | **暫停投票** / **繼續投票** | 顯示「投票暫停中」，無法送出 |
| 結束 | **結束投票**（二次確認） | 顯示「投票已結束」 |
| 同票時 | 依提示選擇「並列名次」或「加賽後指定名次」 | — |
| 頒獎 | **公布前三名**（兩類別分別公布）→ **開始頒獎** | 頒獎頁開始顯示結果 |
| 典禮 | 頒獎頁按「投影模式」，用 **空白鍵／→／簡報筆** 逐步揭曉 | 榮耀時刻 → 第三名 → 第二名 → 第一名 → 完整名單 |
| 會後 | 「資料匯出」下載統計報表、參與名冊、得獎名單；頒獎頁「匯出 PNG」 | — |

**頒獎頁快捷鍵：** `空白鍵`／`→`／`PageDown` 下一步、`←` 上一步、`F` 全螢幕、`H` 隱藏／顯示工具列。

**學生遺失代碼：** 後台「名冊與代碼」找到該生 → **補發代碼**（僅限尚未投票者；舊代碼立即失效）。

## 四、常見問題

**Q：學生換手機、重新整理、關掉瀏覽器，能再投一次嗎？**
不能。是否已投票記錄在雲端資料庫，以「投票者 × 輪次」唯一約束保證每人只有一張選票，與手機、瀏覽器、Cookie 無關。

**Q：同一個代碼在兩支手機同時按送出呢？**
資料庫會鎖定該投票者資料列，只有一支成功，另一支會顯示「您已完成投票」。

**Q：可以中途修改名單或「是否允許投自己組」嗎？**
不行。開始投票後，名單、投票資格與規則會鎖定，避免統計不一致。作品名稱則隨時可改。

**Q：想再辦一次投票？**
投票結束後，「設定」→ **建立新一輪**。舊選票保留作紀錄，新一輪從 0 票開始；代碼沿用，必要時可在開始前重新產生。

**Q：QR Code 頁面顯示黃色警告？**
代表目前不是從正式 HTTPS 網址開啟後台（例如直接雙擊本機檔案）。請從 GitHub Pages 網址開啟後台再產生 QR Code。

**Q：Supabase 免費專案會暫停嗎？**
免費專案長時間沒有使用時，Supabase 可能會將專案暫停。**活動前一天**請登入 Supabase 確認專案狀態為運作中；若顯示暫停，按 Restore 即可恢復，資料不會遺失。

**Q：畫面顯示「尚未完成雲端資料庫設定」？**
`config.js` 尚未填寫或填錯，請重新檢查步驟 4。

## 五、安全設計說明

- **資料表不對外開放**：所有資料表位於私有 schema `awards`，並啟用 Row Level Security 且不建立任何開放政策；瀏覽器無法直接讀寫任何資料表。
- **只能透過伺服器端函式操作**：學生只能呼叫 4 個公開函式（讀取狀態、驗證代碼、提交選票、讀取已公布結果）；管理函式只授權給登入者，並再檢查是否列於管理員名單。
- **代碼安全**：8 碼代碼以密碼學亂數產生（約 8.5×10¹¹ 種組合，排除 0/O、1/I/L 等易混淆字元）；資料庫只保存 SHA-256 雜湊，明碼只在產生當下顯示一次。連續猜錯過多會暫停驗證。
- **一次性選票**：單一交易內完成「狀態檢查 → 資格檢查 → 選票內容檢查 → 寫入」；任何一步失敗整筆回復，不會留下部分票數。
- **開始／暫停／結束與提交互斥**：結束投票生效後，伺服器拒絕所有新選票。
- **結果保密**：教師按下公布前，公開函式不會回傳任何得獎結果；學生端在任何時候都拿不到票數與他人的選擇。匯出報表也不含個人選票內容。
- **同票不擅自決定名次**：前三名有同票時，系統拒絕自動公布；「加賽後指定名次」只允許在同票組別間調整，與實際票數不符會被伺服器拒絕。
